# Original data preparation recovery

The targeted Linux and macOS runs passed 17 controls each. The preparer used
only the original published 56-pair diagnostic corpus. It committed 32 pairs,
staged 52 inside the next SQL transaction, and was actually killed with SIGKILL.
A separate reader observed the 32-pair durable generation before the kill.

The independent verifier rebuilt every committed position, target and contributor
from the original first 32 game pairs, then reconstructed all 56 pairs and all
three final splits after recovery. The resumed arrays and lineage records matched
the uninterrupted run byte for byte and retained the published original arrays.
No games, teacher labels or trained weights were generated or replaced.

The controls include rehashed SQL, game, signal, export and contributor forgeries;
immutable full-bundle staging; two actual full-entry forgeries; and refusal of
the diagnostic barrier in full-follow mode. The first local scratch-directory
failure and both first hosted fixture-directory failures remain published with
their actual source identities. The original execution ceilings were not changed.

The exact raw SQLite/WAL snapshots, original corpus, recovered exports and control
records remain in the hosted artifacts identified by `VERIFICATION.json`.
Portable bulk retrieval remains pending while timed matches own the local host.
This passes the data recovery component, not full G11 or project acceptance.
All required components still need an explicit final source/native-image join.
