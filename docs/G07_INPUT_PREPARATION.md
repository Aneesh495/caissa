# Original-learning audit inputs

`tools.g07_inputs` prepares the actual input catalogs after the frozen strength
sequence settles. It creates no games, gradients, new model selection or
replacement learning receipt. Existing original directories are read only.

The data catalog names all 114,791 original pair hashes, the original failed
acquisition records, held-out inputs and every prepared array/identity journal.
Its selected-view manifests are written into the new preparation directory.
Raw corpus files are not copied or regenerated during catalog preparation.
The independent data reader later checks their actual bytes and semantics.

The learning bundle receives verified streaming copies of all three seeds and
240 checkpoint generations, original initialization/configuration/optimizer
provenance, baseline inputs and the selected checkpoint. The original q1024
network remains the learned export. Its q4096 encoding is a separate deployment
artifact joined through the identical selected float checkpoint.

One preparation has a fixed output, at most one hour of cumulative wall/active
time, 20 GiB additional output and a 10 GiB free reserve. Every hash and copy
checks the resource guard between one-megabyte blocks. Failed outputs remain;
changing directories cannot renew that scope.

The emitted plan and manifest hashes pin a distinct bounded live audit. The
optional audit launch executes the saved source tree against trusted Git blobs,
so unrelated later commits cannot change queued verifier code. The normal live
checkout path still requires its exact HEAD and bytes. A prepared input bundle
certifies no full G07 gate until both independent full readers actually finish.

Hosted controls use the real 50-pair CI corpus, bounded streaming-copy inputs,
forged hash inventories and a deliberately incomplete full-learning fixture.
They claim no ten-million-position or 240-checkpoint positive replay.
