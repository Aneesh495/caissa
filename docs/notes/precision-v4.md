# A finer integer lattice without changing the learned model

The full-data selected q1024 network failed its numerical gate: maximum float/integer discrepancy 57.055664 cp against the unchanged 32 cp limit. Independent float64 replay confirmed the failure. Its three completed training seeds, selected checkpoint and active strength campaign remain immutable.

The prospectively frozen [precision profile](../../config/precision-v4.json) tests one q4096 encoding of that same selected float checkpoint. Seed 73 at step 2750 remains selected by the original v3 validation-only procedure. This experiment performs no training, calibration, checkpoint replacement or model selection from numerical probes or match results. The original checkpoint is included with its [identity](../../results/precision-v4-inputs/IDENTITY.json). Format 3 export must still reproduce the original network byte for byte before format 4 is tested.

The new format uses scale 4096 and integer activation cap 8188. The equality `8188/4096 == 2047/1024` preserves the exact real activation ceiling; using 8191 would subtly change the float function. Tensor shapes, payload size, int16 weights, bounded int32 biases, original classical contract 1 and ten-percent mixture are unchanged. The independent byte reader and checkpoint-to-export verifier require the new format explicitly. Legacy full-profile verification cannot silently accept it.

NEON lane safety changes with the activation range. The existing 128-input blocks place at most 32 products in a signed int32 lane. At the higher resolution that could overflow. The q4096 path uses 32-input blocks, at most 8 products per lane, so `8 * 8188 * 32768 = 2146435072 < INT32_MAX`. Each block widens to int64 before combining blocks or biases. AVX2 also uses the conservative 32-input bound. Scalar, remainder and four-output dense paths use the same signed rounding and real clipping semantics. The old q1024 path retains its 128-input specialization.

The [native tests](../../tests/network_precision_test.cpp) generate original nonzero format 4 fixtures, check incremental state, undo, scalar/SIMD parity, score intervals and malformed numerical/baseline headers. Dot and dense tests include maximum activations, signed weight extremes, chunk boundaries and odd dimensions. The [export checks](../../tests/precision_export.py) independently compare 1024 actual native outputs, verify every exported tensor against the original checkpoint, preserve legacy bytes and reject a changed real cap.

The [hosted campaign](../../.github/workflows/precision-v4.yml) builds and tests on Linux and macOS, then runs 100000 fresh frozen reachable probes, independent float64/integer replay and 1000000 restoration transitions. The 32 cp raw and clamped error limit is unchanged. Compilation and model inference run remotely to avoid competing with the active timed matches. The profile has one original two-hour wall deadline, at most three 1800-second workflow executions per platform and no GitHub job reruns. Earlier negative artifacts are never overwritten. This protocol was frozen before the new numerical results. A numerical pass establishes neither Elo nor release readiness.

Both platforms passed their full numerical sample and all eighteen Release cases. Independent float64 replay measured maximum error 10.394590 cp, mean 1.107676 cp and p99 4.881201 cp. Native, scalar and independent integer results agreed. Both platforms completed 1000000 restoration transitions and produced identical network bytes, SHA256 `52d0306143392ad683c3ebb09fe013f34e1f9e2bc44d3aa153b32314207374b7`. This is a fresh frozen probe set; its maximum is not a paired comparison against the earlier failed q1024 sample.

The [complete compressed raw artifacts](../../results/precision-v4-2026-10-25/MANIFEST.json) include both platform observations and receipts. The exact executables were recovered from the parallel correctness workflow at the same source commit; their hashes match the precision receipts exactly. The original float checkpoint and legacy export remained unchanged. The q1024 failure remains failed, and the active matches continue using their original q1024 executable/network. The q4096 network has no measured playing strength. Final deployment loss, sanitizer/race coverage and whole-project source-bound acceptance remain separate work.
