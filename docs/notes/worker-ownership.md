# Response failure and process ownership

The position service admits at most four concurrent native commands. A request can fail before its child exits: an output-limit violation or deadline rejects the response and sends a kill signal. Releasing capacity at that point lets a replacement overlap the still-owned process. The process reservation now remains occupied until Node reports `close`, after process exit and pipe closure. Spawn failures that throw synchronously release their reservation separately. Asynchronous spawn errors still release through `close`.

The [native transport](../../analysis-service/native.ts) stops collecting output after settlement, caps stdout by received bytes before decoding, and preserves UTF-8 characters across pipe chunks. Diagnostic stderr is capped independently. Shutdown sends TERM, followed by KILL after 200 ms for children still owned by the service. Analysis workers also retain their reservation until `close` on executable errors.

The [adversarial transport test](../../tests/service_workers.mjs) fills all four slots with bounded subprocesses, checks a fifth request receives backpressure, forces oversized output and timeouts, and checks that rejection still owns a slot until close. It also checks invalid JSON, a split multibyte character, synchronous spawn rejection, shutdown cleanup, and usable capacity afterward. These subprocesses exercise transport failures; they are explicitly separate from the [original-engine integration test](../../tests/service_integration.mjs). The latter imports PGN, applies a legal move, analyzes with Caissa, and cancels the analysis.

Run `npm run build` and `node tests/service_workers.mjs`. The transport test has its own 15-second deadline and each command retains the ordinary response timeout. Ordinary Linux and macOS CI runs both transport and original-engine integration. Passing transport checks establishes worker accounting and response handling, not chess strength or final browser acceptance.
