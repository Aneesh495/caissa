# Incremental reversible-history search identity

The previous `Position::search_key` rescanned the known reversible sequence on every transposition lookup. The new implementation maintains a 64-bit polynomial `H = H * 0x9e3779b185ebca87 + repetition_key` when an actual move enters history. Arithmetic is unsigned modulo 2^64. A pawn move or capture resets H before the new position enters it. A FEN starts with its one known position, even when its rule clock is nonzero. Castling retains the reversible sequence, as it did before this change. The existing board hash already contains changed rook-origin rights.

Let L be `min(history.size(), halfmove + 1)` and M be the existing SplitMix64 avalanche. The score identity is `board_key XOR M(H XOR M(halfmove + 20000) XOR (L * 0xd6e8feb86659fd93))`, with `M(30000 + synthetic_depth)` additionally XORed for synthetic search. This fingerprints the ordered known sequence, its length, rule clock and synthetic context. It has the same finite 64-bit collision limitation as the old tag. The hash policy changes, so table bucket layout and selective traversal can change. No global tree-equivalence claim follows.

`Undo` saves H. Null moves change neither H nor game history; their separate synthetic-depth tag prevents importing a real-path score. Actual moves below a null node update and restore H normally. `Position::coherent` reconstructs H slowly from public history for debugging. Search lookup is constant time, and appending and restoring H each take constant time. The fingerprint adds eight bytes to each `Position` and `Undo`, subject to struct padding.

The native test expands the polynomial backwards using powers of the multiplier rather than the production append operation. It compares one million seeded make/unmake transitions, null branches with real descendants, 1024-ply histories, equal-clock different paths, pawn/capture resets, promotion, en passant, standard and overlapping Chess960 castling, large FEN clocks and full stack restoration. Sixty table-on/off and shuffled-root searches agree with independent mailbox minimax across repetition and 50/75-move boundaries. An injected table score cannot cross a known-history/FEN boundary.

All 16 Release and all 16 AddressSanitizer/UndefinedBehaviorSanitizer cases passed. The first configure attempt failed because CMake was absent from the inherited PATH. The failure is retained; recovery used the installed Homebrew tools within the original cumulative 1800-second ceiling. This is a current-core diagnostic, separate from final selected-model and race acceptance.

The lookup microbenchmark alternates order over seven repeats, with 100000 lookups per observation and a compiler memory barrier in both implementations. Median incremental cost was 3.85 to 4.04 ns across the six history lengths. The previous scan rose from 4.58 ns for the shortest fixture to 4489.79 ns at 1024 plies. The very long fixtures test protocol/history scaling; ordinary games terminate at automatic draw boundaries.

The paired executable study retained 180 searches at 50000 requested nodes across ten positions, three repeats and classical/10-percent-mixture/pure-neural evaluation. Both binaries used one thread, 16 MiB hash, static evaluation cache and tactical generation. Two fixtures contain nonrepeating 16/64-ply quiet histories. Median new/old roundtrip ratios were 0.94223, 0.95678 and 0.96576. Original-data replay was active. These descriptive timing observations do not establish isolated performance or playing-strength gain. An independent parser and native transport reproduced all 180 cases, including work counters, score, PV and best move.
