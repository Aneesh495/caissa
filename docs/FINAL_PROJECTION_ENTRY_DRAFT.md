## Prepared child checks

The scope must have the dedicated decision-entry schema, a fixed deadline within
the new authority window, one entry start and zero native, browser, compiler,
training, inference, game, new parallel starts or extra parallel active seconds.
Its origin must follow the newly recorded human instruction. Safe Python startup
requires the admitted environment, interpreter digest, project cwd and `-B -P`.
The resolved source Git executable also needs its own admitted path and digest.
The bootstrap rehashes its bounded pinned source graph before importing project
code. The unchanged full source/input admission then checks the actual product.

The external scope digest is supplied by the trusted admitted parent. It is
never taken from the scope, evidence manifest or domain declarations. The human
record's literal text is a provenance record, not a machine-generated approval.
The trusted admission process must check that it came from the real human reply.

Scope, authority and parent-record reads use bounded stable descriptors with
no-follow traversal and private single-link regular files. The child consumes
the prewritten pipe token, checks its external scope pin, nonce, parent PID,
invocation number and recorded token digest, closes it and removes its environment
entry. A pipe alone does not enforce the parent's cumulative start count. The
actual parent must enforce that count and cannot issue replacement tokens.

The child requires the real inherited host lease and piped output. Its read-only
audit hook allows only the three exact source Git commands, at most three calls,
bounded FIFO write-opens and the null sink. It rejects regular-file mutation and
network calls. File-size and core limits are zero; CPU and bootstrap wall limits
are finite and then clipped to the admitted remaining deadline. This is pinned
writer enforcement, not an OS sandbox or protection from arbitrary native code.

Only after those checks does the draft call the actual projection with the
scope-pinned evidence, source commit and input digest. The optional external
audit receipt path and expected digest also come from the independently pinned
admission, separately from all Bundle/fixture data. No receipt is supplied here.
Source and HEAD must remain frozen from the real audit to the final entry, as
described in [the external trust design](FINAL_AUDIT_EXTERNAL_ROOT_DRAFT.md).

The entry derives exit 0 or 2 from the actual projection and rejects inconsistent
