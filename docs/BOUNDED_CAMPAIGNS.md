# Bounded campaign execution

`make learning-audit RUN_ID=demo-001` runs a finite original learning demonstration in a new directory. It freezes its native executable, generates 400 original games with a 2000-node teacher, prepares and independently replays the data, freezes classical scores, trains three 100-update seeds, selects on validation, independently verifies learning, checks the selected network in the native executable, and invokes four semantic mutation controls. Test arrays remain unopened by training and selection. This is a diagnostic, with no full-data or strength pass.

The first local integration completed eleven stages in about 338 seconds while the full original corpus continued. Its selected model separately passed 1000 native/scalar/reference probes within the 32 cp bound. The combined command now includes that numerical stage. [Execution receipts](../results/bounded-campaign-2026-10-22/CAMPAIGN.json) preserve the actual initial workload and do not relabel it as a full acceptance run. The manually dispatched `learning diagnostic` workflow repeats the complete command from a clean Linux checkout and retains data, models, checkpoints, logs and controls. Ordinary correctness CI remains smaller.

[The process owner](../tools/campaign_process.py) runs explicit argument vectors without a shell. Each stage gets its own process group, finite wall and monotonic deadlines, a bounded output file and an actual exit record. Overall campaign time also limits every remaining stage. SIGTERM starts a two-second cleanup grace, then SIGKILL ends stubborn owned workers. A parent that leaves a descendant or an open output pipe fails. Output flooding records discarded bytes and fails instead of growing a log indefinitely. Startup exceptions and unsuccessful exits remain visible.

`COMMANDS.jsonl` records starts, finishes and exceptions with arguments, timing, actual reaped-child CPU, exits and log hashes. `PROGRESS.json` identifies the active phase. Elapsed time alone is not a useful-work counter: inspect the underlying pair, preparation or checkpoint progress too. The finite deadline bounds phases that produce no intermediate output. CPU accounting describes reaped descendants only; a failed orphan is not assigned an invented total.

The owner never retries or resets a scientific budget. A failed run directory remains immutable. Resume the underlying corpus, preparation, training or arena only with its exact saved inputs and budget ledger. A new wrapper cannot erase those cumulative limits. [Recovery instructions](RECOVERY.md) describe those contracts. Capture a stalled phase, try a materially different bounded recovery and stop looping after three failed approaches.

Actual process controls exercised a successful native command, exit 7, an output flood, a child ignoring termination and an orphaned descendant. They checked exact log caps and cleanup. These are synthetic lifecycle tests, not chess or strength evidence.

The [clean Linux run](../results/linux-learning-2026-10-22/MANIFEST.json) subsequently completed all twelve stages in about 91 seconds and retained its artifacts. Downloaded games, data, models and checkpoint generations independently replayed on macOS. This duration is an observed campaign time, not an isolated hardware comparison.
